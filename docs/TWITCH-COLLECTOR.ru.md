# Twitch collector: короткая инструкция

## Как запустить сбор

1. В **Accounts** создайте YouTube-аккаунт, подключите Google и подтвердите нужный
   канал. Его состояние должно быть `connected`.
2. Откройте **Twitch → Настройки сервиса**. Проверьте наличие Twitch credentials,
   включите collector и сохраните настройки.
3. В **Twitch → Потоки** создайте поток: выберите подтверждённый YouTube-канал,
   Twitch-каналы по логинам/ссылкам или категорию, фильтры и форматы.
   Для первого запуска оставьте ручной режим. Изменение интервала само по себе сбор не включает.
4. Поток и его Twitch-каналы не должны быть на паузе.
5. Нажмите **Проверить сейчас**. Это запускает проверку без ожидания интервала; кнопка
   недоступна, пока collector остановлен или конфигурация блокирует работу.
6. Найденные клипы появятся в **Twitch → Клипы**. Подходящие источники
   скачиваются по одному и импортируются в Terex; отдельно видны состояния исходника и выпусков.
   Просмотрите результат, одобрите нужную версию и назначьте публикацию в календаре.

Подробно о потоках, автоматическом режиме и подборках: [инструкция](TWITCH-FLOWS.ru.md).

Панель обновляет состояние раз в 10 секунд, пока вкладка открыта. Интервал 1 минута
означает повторную проверку примерно раз в минуту, а не новое видео каждую минуту.

## Почему клипов нет

- Collector по умолчанию выключен. Включите сбор и активируйте поток с подтверждённым
  YouTube-каналом. Причина остановки показывается в настройках и карточке потока.
- Ищутся клипы, **созданные** за `Recent clips window`, по умолчанию последние
  72 часа. Наличие старых популярных клипов на Twitch не означает, что они попадут в выборку.
- Для скачивания по умолчанию нужны 100 просмотров, возраст от 60 минут и
  длительность 5–60 секунд. Для диагностики можно временно расширить окно и
  уменьшить порог просмотров / минимальный возраст в настройках потока.
- Один клип повторно не скачивается. По умолчанию доступны две новые загрузки
  от одного канала и десять всего за сутки; смена интервала эти лимиты не сбрасывает.
- При 40 источниках, ожидающих обработки/проверки, новые загрузки останавливаются.
- `Not checked yet` у канала означает, что проверка этого канала ещё не завершалась.
  Проверьте причину остановки, ошибку канала и логи; для ручного обновления есть **Refresh**.
- `discovered` означает, что сохранены метаданные, а задача скачивания ещё не создана.
  Если подходящих клипов много, но `reserved=0` и есть ошибка постановки в очередь,
  проверьте **Last check message** и ERROR-логи: они показывают операцию и код PostgreSQL.
  Ошибка `42725` в проверке пересечений VOD исправляется обновлением collector;
  после обновления нажмите **Check now**, удалять и добавлять каналы заново не нужно.

## Почему не создаётся подборка

Автоматическая подготовка в **Подборках** учитывает выбранный час запуска
(по умолчанию 21:00, Asia/Tomsk) и создаёт один черновик потока за местные сутки.
Для нового потока нужны минимум три готовых источника и 8 минут материала вместе
с перебивками. Источники должны пройти фильтры и ещё не использоваться в подборках
этого YouTube-канала; статус `discovered` для этого недостаточен.
Панель сообщает точную причину и, при нехватке источников, количество исключённых
по каждой причине и недостающую длительность. Для выбора состава без ожидания часа
запуска есть ручная сборка. Старый «Основной поток» сохраняет прежние ограничения
длины до явного изменения настроек.

## Где смотреть логи

В Grafana откройте **Terex → Terex Twitch Collector**. Есть панели INFO, WARNING,
ERROR и все сообщения. В **Explore → Loki** можно выполнить:

```logql
{service="twitch-collector"}
```

Логи показывают причину остановки, начало и итог проверки, количество клипов
по каждому каналу, отбор и постановку в очередь, скачивание, импорт и повторные
попытки. Если клипов для новой загрузки нет, проверка всё равно пишет итог.

Локально:

```bash
docker compose -f docker-compose.yml -f docker-compose.twitch.yml logs -f twitch-collector
```

На стейдже с явно выбранным kubeconfig LT-Inc:

```bash
kubectl --kubeconfig <LT-Inc-kubeconfig> -n admin logs -f deployment/terex-twitch-collector --since=30m
```

Обычного `LOG_LEVEL=info` достаточно; `LOG_LEVEL=debug` добавляет диагностические
сообщения. Для настройки сервиса и ключей см. [Twitch на стейдже](TWITCH-K8S.ru.md).
