# YouTube-потоки: перезаливка популярных Shorts

Поток ищет самые просматриваемые Shorts в выбранных каналах или по поисковым запросам
и публикует их на ваш YouTube-канал. Раздел находится в панели: **YouTube → Потоки**.
Сейчас ролики заливаются без изменений (без баннера, субтитров и перекодирования в вертикаль).

## Как это работает

1. **Источники.** Канал (ссылка, `@handle` или `UC…`) или поисковый запрос (регион и язык необязательны).
2. **Обнаружение.**
   - Для канала RSS — бесплатный сторож: он показывает, что вышло новое видео. Затем читается плейлист
     Shorts канала (`UUSH…`) и статистика — около 2 единиц квоты за обход. Новые видео из RSS читаются
     по 1 единице за пачку из 50, а Short от обычного видео отличает проверка `youtube.com/shorts/<id>`.
   - Поисковый запрос стоит **100 единиц** за вызов (`search.list`, самые просматриваемые, `videoDuration=short`).
   - Просмотры ждущих видео обновляются раз в `refresh_hours`.
3. **Отбор.** Видео моложе `window_hours`, с просмотрами не меньше `min_views` (и `min_views_per_hour`, если задано),
   длительностью в заданных пределах. Лучшим считается видео с наибольшим числом просмотров в час.
   Свои каналы (все подключённые аккаунты) никогда не перезаливаются. Одно видео заливается на канал один раз,
   даже если его нашли два потока.
4. **Окно публикации.** Лучшее видео получает ближайшее свободное окно. Свободные окна считает тот же код,
   что и у Twitch-потоков, поэтому **суточный лимит канала (`twitch_channel_limits`, обычно 5 Shorts) и занятые окна
   общие** для Twitch и YouTube-потоков. Дополнительно у потока есть свои `daily_limit` и `daily_downloads`.
5. **Публикация.** Для видео создаётся обычное задание (режим `whole`: без распознавания речи, один клип на всё видео,
   `source_kind=youtube_flow`, `output_format=short`). Дальше оно идёт тем же путём: скачивание → клип → одобрение →
   публикация на YouTube. В режиме «По апруву» клип ждёт подтверждения на странице **Clips**. Название клипа берётся
   из исходного видео.

## Режим «весь канал»

Флажок **«Весь канал целиком»** в настройках потока отключает окно по возрасту. Берутся лучшие Shorts за всю
историю канала, ранжирование идёт по общим просмотрам (а не по просмотрам в час), `min_views_per_hour` не используется.

- История читается один раз (плейлист Shorts канала, до `max_videos`, не больше 1000; около 2 единиц квоты на 50 видео).
  После включения флажка на уже работающем потоке нажмите **«Проверить сейчас»**: обычный проход историю заново не читает.
- Дальше новые видео ловит RSS-сторож, как и в обычном режиме.
- Для поисковых источников запрос идёт без ограничения по дате (так же 100 единиц).

## Почему видео «ждёт слота»

Задание (скачивание и клип) создаётся только после того, как видео получило свободное окно календаря канала.
Поэтому кандидат из «Ждут слота» не попадёт в **Clips**, пока окон нет. Причина показывается в статусе потока:

- «Нет свободных окон» — дневной лимит канала и его расписание заняты (в том числе Twitch-потоками);
- «Достигнут собственный лимит потока» — `daily_limit` или `daily_downloads`;
- «Нет видео, подходящих под фильтры».

## Квота Google API

Квота считается на весь проект Google (10 000 единиц в сутки по умолчанию; сброс в полночь по тихоокеанскому времени).
Она общая с публикацией и сбором статистики, поэтому потокам выделяется пул:

```
пул = YT_QUOTA_DAILY − YT_QUOTA_RESERVE_PUBLISH − YT_QUOTA_RESERVE_STATS
```

- У каждого потока свой `quota_daily` — жёсткий бюджет в единицах за сутки. Сумма бюджетов включённых потоков
  не может превышать пул (проверяется при сохранении).
- Перед каждым запросом оценка стоимости резервируется в таблице `yt_quota`; если не помещается в бюджет потока
  или в пул, запрос не отправляется. После ответа учёт уточняется по реальной стоимости.
- Если Google всё же вернул `quotaExceeded`, чтение останавливается до конца тихоокеанских суток (`yt_quota_breaker`).
  Уже найденные видео продолжают публиковаться: планирование квоты не требует.
- Чтение идёт токеном подключённого YouTube-аккаунта через `gpu-be` (`Gateway/PublicVideos`), токены main-be не видит.
  Берётся первый рабочий аккаунт; если он требует переподключения или отвечает ошибкой, используется следующий.
  Последний сработавший пробуется первым.

Резервы по умолчанию (`5000` и `1000`) — оценка. **Проверьте реальную квоту проекта и стоимость `videos.insert`
в Cloud Console** и задайте `YT_QUOTA_*` в `k3s/admin/configmap.yaml`: если загрузка стоит 1600 единиц,
5 публикаций в день на канал занимают почти всю базовую квоту.

## Первый запуск

1. В **Accounts** подключите YouTube-аккаунт и подтвердите канал (`connected`).
2. **YouTube → Новый поток**: название, канал назначения, фильтры, окна, бюджет. Поток создаётся выключенным.
3. Добавьте источники, включите поток и нажмите «Проверить сейчас».
4. Найденные видео видны в блоке «Найденные видео», ненужное можно «Пропустить».

## REST (`/api/youtube`)

| Путь | Назначение |
|------|-----------|
| `GET/POST /flows`, `GET/PATCH/PUT/DELETE /flows/{id}` | потоки; `PATCH` принимает только изменяемые поля |
| `POST /flows/{id}/run` | проход сейчас |
| `POST /flows/{id}/sources`, `DELETE /flows/{id}/sources/{sid}` | источники |
| `GET /flows/{id}/candidates?state=&limit=` | найденные видео |
| `POST /flows/{id}/candidates/{video}/skip` | пропустить видео |
| `GET /quota` | пул, расход по потокам, состояние предохранителя |

## Настройки main-be

| Переменная | По умолчанию | Значение |
|-----------|--------------|----------|
| `YT_FLOWS_INTERVAL` | `1m` | как часто запускается проход по потокам |
| `YT_RSS_INTERVAL` | `10m` | минимальная пауза между чтениями RSS одного источника |
| `YT_QUOTA_DAILY` | `10000` | квота проекта Google в сутки |
| `YT_QUOTA_RESERVE_PUBLISH` / `YT_QUOTA_RESERVE_STATS` | `5000` / `1000` | резервы под публикацию и статистику |

## Риски

- Перезаливка чужих роликов без изменений может быть расценена YouTube как повторное использование контента
  (потеря монетизации, жалобы правообладателей, страйки). Согласие автора настройками потока не подтверждается.
- Проверка Short через `youtube.com/shorts/<id>` не использует квоту, но это неофициальный приём; при сбое видео
  не сохраняется и проверяется заново на следующем проходе.
- Скачивание идёт с IP GPU-сервера (`yt-dlp`): при блокировках нужны куки или прокси.
