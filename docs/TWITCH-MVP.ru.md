# Twitch → Terex: запуск MVP

Коллектор читает популярные клипы выбранных каналов с токеном приложения Twitch,
скачивает файлы через yt-dlp и передаёт их через HTTP import API. Terex проверяет
медиа, создаёт полный вертикальный Short и выполняет монтаж и публикацию своим
существующим версионным конвейером. Учётных записей и OAuth стримеров нет.

## Локальный пилот

1. Заполнить значения из `.env.twitch.example` в локальном, игнорируемом Git `.env`.
   Пароль оператора и два служебных токена должны отличаться. Пароль БД коллектора
   использовать в URL-безопасном виде, например случайную строку hex.
2. Запустить `docker compose -f docker-compose.yml -f docker-compose.twitch.yml up --build`.
   Стандартный media image сохраняет прежний конвейер при настроенных на GPU-хосте
   зависимостях yt-dlp/Whisper и их монтировании. Для пилота только
   с Twitch можно выбрать `GPU_DOCKERFILE=gpu-be/Dockerfile.twitch`; этот облегчённый
   CPU image содержит FFmpeg, но не зависимости старого поиска моментов.
3. Открыть `http://localhost:3000`, войти с паролем оператора. Подключить один
   YouTube-аккаунт обычным способом Terex и проверить идентификатор канала.
4. В разделе Twitch выбрать этот аккаунт, добавить сначала два канала по логину
   или URL, сохранить настройки и включить сбор. Нажать «Проверить сейчас».
5. Просмотреть созданные Shorts, при необходимости обрезать начало/конец и сохранить
   новую версию. Одобрить готовую версию, выбрать время и видимость в календаре.
6. В «Подборках» дождаться ежедневного черновика или создать его вручную. Выбрать
   3–10 источников, установить порядок и диапазоны. После завершения рендера
   просмотреть результат и одобрить нужную версию через существующий редактор.

В начальных настройках сбор выключен, пока не выбран аккаунт и не подключены
источники. Twitch app credentials нужны для Helix metadata; подключать стримеров
не требуется. Публикация на YouTube использует OAuth оператора и ручное одобрение.

## Параметры и поведение

Настройки хранятся в Terex и редактируются в панели: проверка каждые 144 минуты,
окно 72 часа, первые 100 клипов, минимум 100 просмотров, возраст от часа,
длительность 5–60 секунд; 10 скачиваний в сутки, 2 от канала, 5 Shorts и 1 подборка
в сутки. Часовой пояс — Asia/Tomsk. Подборка создаётся после 21:00 при наличии
минимум трёх готовых источников. При перезапуске пропущенные проверки не догоняются.

Рейтинг — просмотры, затем новизна и ID. Каждый канал получает первую возможность
до второго кандидата. Идемпотентность обеспечивают Twitch clip ID, ключ импорта,
проверка VOD-интервалов и SHA-256 файла. Один источник может войти в Short и подборку.
Отклонение источника исключает его из новых подборок и останавливает ещё не начатые
выпуски, которые его используют. Приостановка канала сохраняет уже импортированные
материалы. Общая остановка отключает проверки и новые скачивания.

Очередь downloads сохраняется в PostgreSQL. Истёкший lease может забрать другой
worker, а ответ старого worker не принимается. Временно недоступные скачивания
повторяются до трёх попыток с паузами 5 и 30 минут. Вход, удаление и отказ доступа
завершаются ошибкой без обхода. Процесс ограничен 120 секундами и 512 MiB на файл.
Накопление 40 материалов, ожидающих решения, приостанавливает новые скачивания.

Short содержит весь исходник, 1080×1920 H.264/AAC, изображение целиком на размытом
фоне; субтитры и дополнительная музыка выключены. Подборка использует исходные
горизонтальные файлы и закреплённые версии/диапазоны: 1920×1080, 30 fps, H.264/AAC,
одна секунда тихой карточки следующего канала, нормализация звука и добавление
тихой дорожки для клипов без аудио.

Изменение состава создаёт новую версию и снимает одобрение будущих публикаций.
Уже начатый upload остаётся связан со своей версией. Неопределённый ответ YouTube
обрабатывается существующими checkpoints: слепой повтор insert не выполняется.

## Границы доступа

Коллектор слушает только внутреннюю сеть Docker. `COLLECTOR_SERVICE_TOKEN` даёт
Terex доступ к управлению коллектором. `TEREX_SERVICE_TOKEN` разрешает коллектору
только import API и чтение Twitch settings. Он не открывает публикации, аккаунты
или YouTube credentials. DB principal `twitch_collector` владеет только своей схемой
и не получает прав на таблицы Terex.

Import API выдаёт URL для записи ровно одного временного объекта. GPU worker
скачивает его с ограничением размера, проверяет SHA-256, потоки, длительность и
полное декодирование, затем копирует в отдельный проверенный объект. Временный URL
не позволяет переписать готовый исходник. Объекты и версии закрепляются до рендера.

Локальный Compose привязывает опубликованные порты к 127.0.0.1. Для удалённого
пилота необходим HTTPS reverse proxy к панели/API и корректный публичный адрес
MinIO для previews; инфраструктуру не следует открывать в Интернет. Передавать
Basic credentials нужно только по HTTPS вне локальной машины. TLS и развёртывание
на сервере не выполняются автоматически этой реализацией.

## API

| Endpoint | Назначение |
|---|---|
| GET/PUT `/api/twitch/settings` | Общие настройки проекта |
| GET/POST `/api/twitch/channels` | Список и добавление источников |
| PATCH/DELETE `/api/twitch/channels/{id}` | Пауза и архивирование |
| POST `/api/twitch/check` | Ручная проверка |
| GET `/api/twitch/status`, `/api/twitch/clips` | Состояние, найденные клипы и ошибки |
| POST `/api/imports` | Идемпотентная резервация и временный URL |
| POST `/api/imports/{id}/complete` | Проверка файла и постановка рендера |
| GET `/api/imports`, `/api/imports/{id}` | Статус и связанные объекты |
| PATCH `/api/imports/{id}` | Отклонение/возврат источника |
| GET/POST `/api/compilations` | Список и создание черновика |
| GET/PUT `/api/compilations/{id}` | Просмотр и изменение состава |

JSON-контракты находятся в `proto/twitch`; `AssemblySpec` и GPU ingestion RPC —
в `proto/workflow`. API календаря, редактора, OAuth и publisher сохраняются.

## Проверки перед реальным выпуском

Запустить `go test ./proto/... ./main-be/... ./gpu-be/... ./twitch-collector/...`.
`TEST_DATABASE_URL` и `COLLECTOR_TEST_DATABASE_URL` должны указывать на отдельные
тестовые БД (collector tests удаляют только тестовую схему `twitch_collector`). В FE выполнить
`npm test`, `npm run typecheck`, `npm run build`. `MEDIA_SMOKE=1` включает настоящий
FFmpeg smoke, включая разные fps/разрешения, клип без звука и карточки. CI выполняет
эти проверки и PostgreSQL tests автоматически.

Для пилота отдельно выполнить live Helix discovery и скачивание разрешённого
тестового материала; затем private upload на тестовый YouTube-канал, дождаться
processing, проверить отмену и восстановление upload после остановки worker.
Новые непроверенные Google API проекты могут ограничивать загрузки private до
[YouTube API audit](https://developers.google.com/youtube/v3/docs/videos/insert).

Согласие стримеров не запрашивается и не записывается как полученное. Исходная
ссылка и решение оператора сохраняются, но ручное одобрение не подтверждает права
на контент и не гарантирует монетизацию. Пилот не включает автоматический обход
входа/защит Twitch, скорость роста просмотров, AI highlights или мультитенантность.
